# CSharpTestTask

Решение тестового задания на вакансию C# разработчика.

Проект оформлен как стандартное .NET-решение: основная логика вынесена в библиотеку, консольный запуск используется для задачи со стандартизацией логов, проверки вынесены в отдельный тестовый проект.

## Структура

```text
CSharpTestTask/
├── samples/                       # Примеры входных и выходных файлов
├── src/
│   ├── CSharpTestTask.Core/       # Основная логика задач 1, 2 и 3
│   └── CSharpTestTask.Console/    # Консольный запуск для задачи 3
├── tests/
│   └── CSharpTestTask.Tests/      # Автоматические тесты
├── .editorconfig
├── .gitattributes
├── .gitignore
├── CSharpTestTask.sln
└── README.md
```

## Требования

- .NET SDK 8.0 или новее.

## Сборка

```bash
dotnet build
```

## Запуск тестов

```bash
dotnet test
```

## Запуск задачи 3

Пример запуска консольной программы для стандартизации лог-файла:

```bash
dotnet run --project src/CSharpTestTask.Console -- samples/input.txt output.txt problems.txt
```

После запуска:

- `output.txt` будет содержать валидные строки в стандартном формате;
- `problems.txt` будет содержать исходные строки, которые не удалось распознать.

## Задача 1

Реализованы алгоритмы сжатия и восстановления строки, состоящей из маленьких латинских букв.

Пример:

```text
aaabbcccdde -> a3b2c3d2e
```

Особенности реализации:

- последовательный проход по строке;
- `StringBuilder` для эффективной сборки результата;
- поддержка многозначных количеств, например `a12`;
- проверка входных данных;
- тесты на базовые сценарии и некорректные входные данные.

## Задача 2

Реализован статический класс `Server` с методами:

- `GetCount()`;
- `AddToCount(int value)`.

Для синхронизации используется `ReaderWriterLockSlim`, так как по условию:

- несколько читателей могут читать одновременно;
- запись должна выполняться только одним потоком;
- во время записи читатели должны ждать окончания записи.

Дополнительно используется `checked`, чтобы не допустить незаметного переполнения `int`.

## Задача 3

Реализована консольная программа для стандартизации лог-файлов.

Поддерживаются два входных формата:

```text
10.03.2025 15:14:49.523 INFORMATION Версия программы: '3.4.0.48729'
2025-03-10 15:14:51.5882| INFO|11|MobileComputer.GetDeviceId| Код устройства: '@MINDEO-M40-D-410244015546'
```

Выходной формат:

```text
Дата<TAB>Время<TAB>Уровень<TAB>ВызвавшийМетод<TAB>Сообщение
```

Невалидные строки записываются в отдельный файл `problems.txt` без изменений.

## Примечание по формату даты

В тексте задания указан выходной формат даты `DD-MM-YYYY`, но в одном из примеров дата показана как `YYYY-MM-DD`. В решении используется формат `DD-MM-YYYY`, так как он явно указан в требованиях. Формат вынесен в константу `OutputDateFormat`, поэтому при необходимости его можно заменить в одном месте.
